# 読まれる記事の作り方（土木のトリセツ版）

2026-11-04 策定。**note記事もブログ記事も、書く前と出す前に必ずこれを通す。**
中身は全部、実測データが根拠。思いつきのノウハウは入れない。

---

## 大原則

> **読まれない原因は「文章が下手」ではない。**
> **「誰に向けて書いたか」と「どこから来る読者か」がズレているだけ。**

書く力より先に、**読者の特定**と**流入経路の特定**。この2つを外すと、何文字書いても読まれない。

---

## 🔴 noteとブログは、別の生き物

ここを混ぜると全部失敗する。

| | **note** | **ブログ（doboku-torisetsu.com）** |
|---|---|---|
| 読者はどこから来る | タグ・おすすめ・お題。**記事単体で流れてくる** | **Google検索**。答えを探して来る |
| 読者の状態 | 暇つぶし。**読む義務がない** | 困っている。**答えが要る** |
| 勝ち筋 | **感情**（自分のことだと思わせる） | **一致**（検索語とタイトルを合わせる） |
| 1行目 | **名乗りか結果**（誰の話か3秒で） | **結論**（答えを先に） |
| 物語 | **必須** | **要らない**（むしろ邪魔） |
| 成功の指標 | スキ・フォロー | 検索順位・CTR |

### なぜそうなるか

**noteの読者は「読まなくてもいい人」。** タイムラインを流していて、たまたま目に入っただけ。
だから**3秒で「自分に関係ある」と思わせないと消える。** 感情で掴むしかない。

**ブログの読者は「読まないと困る人」。** 「2級土木 過去問 令和7年」と自分で打ち込んで来ている。
だから**掴む必要がない。** 必要なのは「探していたものがここにある」と即座に分かること。物語は時間の無駄。

## 毎回やる4ステップ

### ステップ1：読者を1人に決める

「施工管理を目指す人」では**広すぎて誰にも刺さらない**。

```
❌ 施工管理技士の受検者
✅ 25〜35歳、現場に出ている、資格は無いか2級まで、
   辞めたいが何から動けばいいか分からない、机に向かう体力が残っていない人
```

**書き終わったあと、その1人が読んで「自分のことだ」と思うか**を確認する。

### ステップ2：上位記事を実測する（感覚で決めない）

**note**
```js
// 人気順250本を取る
fetch('https://note.com/api/v3/hashtags/' + encodeURIComponent(tag) + '/notes?order=popular&page=' + p)
// 本文の構造を測る
fetch('https://note.com/api/v3/notes/' + key)  // data.body
```
測る項目：**字数／見出し数／1段落の字数／画像枚数／タイトル長／1行目の型**

**ブログ**
Search Console（`https://doboku-torisetsu.com/` のURLプレフィックス／`/u/1/`）で
**表示回数が多いのにCTRが低いクエリ**を探す。そこが穴。

### ステップ3：自分の記事を同じ物差しで測る

並べて数字で比べる。**「なんとなく良さそう」で出さない。**

### ステップ4：読者目線で読み直す

- 1行目で「誰の・何の話か」分かるか
- 読者が**今日やれること**が書いてあるか
- **「すごい人の話」になっていないか**
- 読者が置いていかれる用語がないか

## note：実測した「読まれる形」（2026-11-03）

#転職体験記・#施工管理の人気順 各250本を実測。

| | 上位（400〜500スキ） | うちの第1回（当初・2スキ） |
|---|---|---|
| 本文 | **1,600〜2,100字** | 783字 |
| 見出し | **6〜7個** | 2個 |
| 1段落 | **40〜46字**（1〜2文で改行） | 26字 |
| 画像 | **0枚** | 0枚 |
| タイトル | 中央値**33字**・連載は**①②** | 23字・番号なし |
| 1行目 | **名乗りか結果** | 上司のセリフ |

### 分かったこと

1. **画像0枚でも500スキ取れる。** サムネより中身
2. **1行目で結果を言ったほうが読まれる。** 471スキの記事は1行目で「ブラック企業を辞めてホワイトに転職した俺だ」と名乗っている
3. ただし**結果の直後に「才能ではない」を置く**。でないと「すごい人の話」になって読者が引く
4. **連載は番号を振る。** ①②があるだけで「続きがある」と伝わる
5. **#施工管理の上位は2種類だけ** — ①経験記述の書き方（459〜476スキ） ②現場の短いエッセイ（215〜259スキ）

### ⚠️ うちの最大の武器

#施工管理で476スキの記事の書き手は、本文でこう書いている。

> 私は施工の実務の経験がないので、現場の経験談は書けません

**未経験の人が書いて476スキ。監督には本物の現場経験がある。** ここが最大の差。使い切る。

## ブログ：実測した「読まれる形」

| 実測 | 示すこと |
|---|---|
| 「○○ 過去問 **令和6年**」CTR **43%** ／ 「○○ 過去問」CTR **1.6%** | **検索語とタイトルの一致がすべて** |
| 「新規入場者教育の記録」10日で**51表示** ／ 「工程表の作り方」42日で**0** | **書類名（固有名詞）で検索される。「作り方」では探されない** |
| 年度なしクエリ7,602表示に受け皿ページが無かった | **検索されている言葉に、対応するページを必ず作る** |

### ブログの型

1. タイトルに**検索語をそのまま入れる**（言い換えない）
2. 冒頭に**結論ボックス**（答えを先に）
3. **表で比較**（文章で説明しない）
4. **デメリットを自分から書く**（信用が生まれる・離脱が減る）
5. 最後に**次の一歩**（クイズ／PDF／関連記事）

## 共通：刺さる書き方

### ① 具体が刺さる。抽象は刺さらない

```
❌ 現場は大変でした
✅ 下道なら窓を開ければやり過ごせる。でも高速道路に乗ると窓は閉まる
```

**その人にしか書けない具体**が1つあれば、読者は「この人の話だ」と思う。

### ② 読者を上から見ない

```
❌ 3人受けて、受かったのは自分だけでした（自慢に読める）
✅ 能力の差ではなく、やった人が少ないだけだと思っています
```

### ③ 悪者を作らない

上司や会社を責めると読者は引く。**「自分はそうなりたくなかった」で止める。**

### ④ 読者が今日やれることを1つ書く

「15年上の先輩に給料を聞いてみてください」「休憩の10分で1問解く」
**大きな変化を求めない。** 一歩だけ。

### ⑤ 正直に書く

デメリット・限界・できなかったことを先に書く。
`施工管理は楽ではない／書類が多い／エージェントは連絡が多い` を書いたほうが信用される。

---

## やってはいけないこと

- ❌ **無いことを書き足して字数を稼ぐ。** 監督の経験談に、私が情景を創作しない。字数が足りないときは**監督に聞く**
- ❌ 年収の具体額・倍率を書く（逆算される）→ 生活の変化で書く
- ❌ 「すごい人の話」で終わらせる
- ❌ 上位記事を見ずに「たぶんこうだろう」で書く
