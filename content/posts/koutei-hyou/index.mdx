「工程表を作れと言われたけど、**書き方を教わっていない**」
「ネットワーク工程表って、実務でも使うの？」
「工程が遅れたとき、**どう立て直せばいいのか分からない**」

工程表は、施工管理の仕事の中で**一番「教わらないまま任される」もの**だと思います。試験ではネットワーク工程表の計算が出ますが、現場で最初に作らされるのはたいてい別物です。

この記事では、筆者が実務でやってきた**エクセルのバーチャート**での作り方と、**工程が遅れたときに班を増やして挽回した経験**をそのまま書きます。

<CalloutBox type="target">
- 初めて工程表を任された新人監督
- ネットワーク工程表は勉強したが、実務でどう使うか分からない人
- 工程が遅れがちで、立て直し方を知りたい人
</CalloutBox>

<CalloutBox type="conclusion" title="この記事の結論">
- 実務の工程表は**エクセルのバーチャートで十分**。ネットワークは大規模工事か試験のためのもの
- 作り方は「**完成日から逆算**」して、工種を並べ、**予定と実績を2段**で書く
- 遅れは「見つける」が9割。**週1回、実績の線を引く**だけで早く気づける
- 挽回の基本は**班を増やす**（人を足す）。残業・休日出勤は最後の手段
</CalloutBox>

## 工程表は「現場の約束事」

最初に、工程表が何のためにあるかを押さえてください。**きれいな表を作ることが目的ではありません。**

| 誰のため | 工程表がないと起きること |
|---|---|
| **協力会社（職人）** | 他の現場も抱えているので、日程を早く伝えないと人が来ない |
| **材料・機械** | 納期がある。発注が遅れると工程ごと止まる |
| **発注者** | 「いつ終わるのか」を説明できないと信用を失う |
| **自分** | 今日やるべきことが分からず、後手に回る |

つまり工程表は、**関係者全員と交わす「いつ・何をやるか」の約束事**です。だから正確さより、**早く作って早く共有する**ことのほうが大事です。

## 実務はバーチャートで十分

工程表には大きく2種類あります。

| | バーチャート（横線式） | ネットワーク工程表 |
|---|---|---|
| 見た目 | 工種ごとに横棒を引く | 矢印と丸で作業の順序をつなぐ |
| 作りやすさ | **簡単。エクセルで作れる** | 手間がかかる |
| 分かること | いつ何をやるか、が一目で分かる | どの作業が遅れると全体が遅れるか（クリティカルパス） |
| 向いている現場 | **一般的な土木・造園工事のほぼすべて** | 工種が複雑に絡む大規模工事 |
| 試験 | — | **1級土木の一次で毎年出題** |

**筆者が実務で使っていたのは、バーチャートです。** ネットワーク工程表は試験のために勉強しましたが、現場で自分で描いたことはほとんどありません。

<CalloutBox type="point" title="ネットワークを否定しているわけではありません">
工種が多く、前後関係が複雑な現場では、ネットワークで「どこがボトルネックか」を把握する価値があります。<br /><br />
ただ、**新人がまず任される規模の現場では、バーチャートで足ります**。試験用の知識は、バーチャートを組むときの「順番の考え方」として頭の中で使えば十分です。
</CalloutBox>

## エクセルでバーチャートを作る手順

筆者はずっとエクセルで作っていました。専用ソフトは使っていません。**会社にひな形があればそれを使ってください。** なければ、次の手順で作れます。

### 手順1：完成日（ゴール）を先に決める

工程表は**後ろから作ります**。

- 引渡し日・完成検査日
- 中間検査の日
- 発注者との約束の日

これらを**先に書き込んで**、そこから逆算して各工種の日程を決めます。前から積み上げると、最後に「間に合わない」が発覚します。

### 手順2：工種を縦に並べる

縦軸に工種を、**施工する順番で**上から並べます。

```
準備工
仮設工
土工（掘削）
土工（埋戻し）
基礎工
構造物工
舗装工
付帯工
片付け・検査
```

最初は**大きな工種だけ**で構いません。細かくしすぎると更新が追いつかなくなります。

### 手順3：横に日付を並べ、休日を塗る

横軸は**1日1列**。土日・祝日・現場の休工日は先に色を付けておきます。**これを忘れると、日数の計算が全部ずれます。**

### 手順4：各工種の日数を出す

日数は「数量 ÷ 1日にできる量」で出します。

> 例：掘削 500m³ ÷ 1日100m³ ＝ **5日**

1日にできる量（歩掛）は、**協力会社に直接聞くのが一番正確**です。「これ、何日で終わりますか？」と聞けば教えてくれます。新人が自分で見積もるより、はるかに確かです。

<CalloutBox type="warn" title="雨の日を見込んでいますか">
土工は雨が降ると止まります。**カレンダー通りの日数で組むと、必ず遅れます。**<br /><br />
その地域・その時期の雨の日数を見込んで、**余裕日（予備日）を入れておく**のが実務のコツです。梅雨や台風の時期は特に厚めに取ってください。
</CalloutBox>

### 手順5：予定と実績を「2段」で書く

**ここが一番大事です。**

各工種の行を上下2段にして、**上段に予定の線、下段に実績の線**を引きます。

```
土工（掘削）  予定 ■■■■■
              実績 ■■■□□  ← 2日遅れているのが一目で分かる
```

予定だけの工程表は「作った日」で役目を終えます。**実績を書き足していくことで、初めて「使える工程表」になります。**

## 全体・月間・週間の3つを使い分ける

実務では、粗さの違う工程表を**3種類**使います。

| 種類 | 粗さ | 主な用途 |
|---|---|---|
| **全体工程表** | 工種単位・工期全体 | 発注者への提出、全体の見通し |
| **月間工程表** | 週〜日単位 | 協力会社への手配、材料の発注 |
| **週間工程表** | 日単位・作業単位 | **職人さんへの指示、朝礼で使う** |

**現場で一番使うのは週間工程表です。** 「今週は何曜日にどの班が入って、何をやるか」がここで決まります。

全体工程表は、着手時に1回作ったら、あとは月に1回程度の見直しで足ります。

## 遅れは「見つける」が9割

工程が遅れる原因は、だいたい決まっています。

- 天候（雨・雪・猛暑）
- 材料の納期遅れ
- 前の工程が終わっていない
- 設計変更・現場条件の違い（地中の障害物など）
- 人が集まらない

どれも**ある日突然、1週間遅れる**わけではありません。**1日、また1日と積み重なって**、気づいたときには取り返せなくなっています。

だから対策は単純で、**週に1回、実績の線を引く**。これだけです。線を引けば、予定との差が目に見えます。

<CalloutBox type="point" title="金曜の夕方に線を引く">
筆者のおすすめは、週の終わりに来週の週間工程表を作るついでに、今週の実績線を引くことです。<br /><br />
「予定より2日遅れている」と**数字で分かった時点で**、翌週の手配を変えられます。月末に気づいたのでは、協力会社の都合がつきません。
</CalloutBox>

## 遅れたときの挽回策

### 基本は「班を増やす」

**筆者が実際にやったのは、班を増やすことです。** 1班で進めていた作業に、もう1班入れる。単純ですが、これが一番効きます。

ただし、条件があります。

| 条件 | 理由 |
|---|---|
| **作業エリアを分けられる** | 同じ場所に2班入れても、ぶつかって効率が落ちる |
| **監督が両方を見られる** | 班が増えれば、指示・確認・写真も倍になる |
| **協力会社に早く相談する** | 人は急には集まらない。遅れに気づいたらすぐ連絡 |

3つ目が特に重要です。**「来週から2班でお願いできますか」は、遅れに気づいた週のうちに**言ってください。1週間後では手遅れです。

### そのほかの挽回策

| 方法 | 内容 | 注意点 |
|---|---|---|
| 並行作業 | 順番にやる予定だった工種を同時に進める | 干渉しないか確認 |
| 機械を大きくする・増やす | 掘削機のサイズアップ、ダンプの台数追加 | 搬入路・置き場の確保 |
| 工種の順番を入れ替える | 天候に左右されない作業を雨の日に回す | 前後関係を崩さない |
| 残業・休日出勤 | 稼働時間を増やす | **最後の手段**。安全と品質が落ちる |

<CalloutBox type="warn" title="挽回のしわ寄せは、安全と品質に来ます">
急げば急ぐほど、確認が雑になります。班を増やしたなら、**写真と検査の段取りも増やしてください。**<br /><br />
挽回して工期に間に合っても、**やり直し工事が出たら意味がありません。**
</CalloutBox>

### 自分の責任でない遅れは、記録を残す

天候・設計変更・地中障害物など、**施工者の責任でない遅れ**は、工期延長の協議材料になります。

ただし、**記録がなければ協議になりません。** 雨で休んだ日、障害物が出た日は、**日付と写真**を残してください。詳しくは → [施工写真の撮り方【写真が残っていないと検査に落ちます】](/posts/sekou-shashin)

## よくある質問

### Q1. 工程表は何日かけて作ればいいですか？

**最初の版は1〜2日で作って、すぐ共有してください。** 完璧なものを1週間かけて作るより、粗い版を早く出して協力会社の意見で直すほうが、結果的に正確になります。

### Q2. 歩掛（1日にできる量）が分かりません。

**協力会社に聞いてください。** 「この数量、何日で終わりますか」と聞けば答えてくれます。会社の過去の工程表や、先輩の現場の実績も参考になります。

### Q3. 遅れを上司や発注者に言いにくいです。

**遅れは早く言うほど選択肢が残ります。** 隠して月末に発覚すると、挽回策が残業しかなくなります。「2日遅れているので、来週から班を増やします」と、対策とセットで報告すれば、怒られることはまずありません。

### Q4. 専用の工程表ソフトは必要ですか？

**新人のうちは不要です。** エクセルで十分ですし、会社にひな形があるならそれを使うのが一番です。ソフトは、大規模現場やネットワーク工程表を本格的に運用する段階で検討すれば足ります。

## まとめ

| 項目 | ポイント |
|------|---------|
| **種類** | 実務は**バーチャート**で十分。ネットワークは試験と大規模現場 |
| **道具** | **エクセル**。会社のひな形があればそれを使う |
| **作り方** | 完成日から逆算 → 工種を順に並べる → 休日を塗る → 日数は数量÷歩掛 |
| **一番大事** | **予定と実績を2段で書く**。実績を書いて初めて「使える」 |
| **使い分け** | 全体・月間・**週間**。現場で一番使うのは週間 |
| **遅れ** | 週1回の実績線で早く気づく。挽回は**班を増やす**、残業は最後 |
| **記録** | 自分の責任でない遅れは、日付と写真を残す |

工程表は、作った瞬間より**更新し続けることに価値があります**。まずはエクセルで粗い版を作って、金曜の夕方に線を引く習慣から始めてみてください。
